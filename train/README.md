# Обучение сидов (seeds/train)

Цель: дообучить `Qwen/Qwen2.5-Coder-1.5B-Instruct` так, чтобы 4 фиксированных **сида** давали алгоритмически
разные правильные программы. Тогда «по одному решению на сид» решает больше задач (pass@4), чем 4 независимых
сэмпла, а правильные решения разных сидов попадают в разные группы исполнительного отпечатка (exp0).
В цикле обучения нет LLM-судьи: награда считается из тестов и трассировки.

## Запуск

Скопируйте на сервер всю папку `seeds/` (нужны `seeds/exp0/src`, `seeds/exp0/data/tasks_53d89291.jsonl` и
`seeds/train`). Затем одна команда:

```bash
bash seeds/train/run.sh
```

Скрипт сам:

1. проверяет окружение (`python3` с torch + transformers и CUDA; если его нет — создаёт `.venv`);
2. делает **пробный прогон** в консоли на настоящей модели с крошечными размерами (10–20 минут); при ошибке
   полный запуск не стартует;
3. запускает **полный запуск в фоне** (около 26–30 часов на 4 GPU) и печатает, как за ним следить.

Повторный запуск той же команды продолжает с места остановки.

| что | команда |
|---|---|
| состояние | `cat seeds/train/runs/main/STATUS.md` |
| общий лог | `tail -f seeds/train/runs/main.log` |
| лог одной задачи | `seeds/train/runs/main/logs/<job>.log` |
| остановить | `kill $(cat seeds/train/runs/main.pid)` |
| отчёт (в любой момент) | `RUN_NAME=main python3 -m st.report` из `seeds/train` → `runs/main/report.md` |

## Этапы полного запуска

| этап | что делает | время |
|---|---|---|
| model | скачивает веса (3.1 ГБ) | 5 мин |
| prep | вводные задачи APPS (обучающая часть с ≥5 тестами и остаток тестовой части, которого нет в отложенных 400 задачах exp0) → задачи, проверка эталонных решений тестами, отбор 150 задач для валидации | 30–40 мин |
| probe | базовая модель решает каждую задачу 8 раз (все GPU) | 30–40 мин |
| pool | в обучение идут задачи, которые базовая модель хоть раз решила (+10% нерешённых); трассировка эталонных решений: лестница входов, эталонные ответы и время на увеличенных входах | около 1 ч |
| calib | 3 шага каждого варианта одновременно → число шагов S под `TRAIN_HOURS` (одинаковое для всех) | 15 мин |
| train | 4 обучения параллельно, по одному на GPU | 19 ч |
| final | базовая модель и каждый вариант на валидации и на 400 отложенных задачах (4 сида × 4 сэмпла) | 3–4 ч |
| report | `runs/main/report.md` | — |

Варианты обучения (`VARIANTS`):

- `film_full` — **наш метод**: сид умножает нейроны MLP (`нейроны * nn2(seed)`), награда с разнообразием;
- `none_correct` — главная базовая линия: GRPO без сидов, награда только за правильность;
- `prompt_full` — сид текстом в подсказке («Strategy s.»), та же награда;
- `film_correct` — сиды без награды за разнообразие.

## Награда

Для задачи генерируется группа: 4 сида × 4 решения. `R = c · (1 + λ·D + γ·S)`:

- `c` — решение проходит все тесты и на увеличенных входах даёт те же ответы, что эталонные решения
  (подгонка под видимые примеры не проходит);
- `D` — среднее расстояние отпечатка до правильных решений **других** сидов;
- `S` — близость к правильным решениям **своего** сида;
- расстояние учитывает рост времени работы и схему вычислений; набор использованных структур данных выключен
  (его легко накрутить лишним `sorted()`);
- **слишком медленные** решения (в 20+ раз медленнее самого медленного эталонного и дольше 50 мс на входах до 64×
  от тестовых) получают награду только за правильность, без бонуса за разнообразие;
- решения, у которых отпечаток измерить не удалось, получают средний бонус группы (ни награды, ни штрафа).

## Основные настройки (переменные окружения, см. `st/config.py`)

| переменная | по умолчанию | смысл |
|---|---|---|
| `TRAIN_HOURS` | 19 | время на обучение; число шагов подбирается калибровкой |
| `STEPS` | 0 | задать число шагов вручную (тогда калибровки нет) |
| `GPUS` | все свободные | например `GPUS=0,1,2,3` |
| `VARIANTS` | 4 варианта | `имя:режим:награда` через запятую, в порядке приоритета |
| `LAMBDA`, `GAMMA` | 1.0, 0.5 | веса D и S |
| `SLOW_FACTOR`, `SLOW_MAX_SCALE` | 20, 64 | порог «слишком медленно» |
| `P_TASKS`, `M_PER_SEED` | 8, 4 | задач на шаг и решений на сид |
| `LR`, `FILM_LR_RATIO` | 5e-5, 4 | шаг обучения LoRA и множитель для сети сидов |
| `DISK_LIMIT_GB` | 20 | предел места для `seeds/train`; при превышении запуск останавливается |

## Диск

Веса 3.1 ГБ, данные и кэши до 1 ГБ, контрольные точки около 1 ГБ на вариант — всего около 9–10 ГБ
(плюс ~7 ГБ, только если пришлось создавать `.venv`). Всё лежит внутри `seeds/train`.

## Что смотреть в отчёте

- `pass@N seeds` у `film_full` против `none_correct` и `base` (таблица парных разностей с доверительными
  интервалами);
- `groups/draw` — сколько разных групп отпечатка среди правильных решений в наборе «по одному на сид»;
- `gap = d cross − d same` > 0 — сиды действительно означают разные алгоритмы;
- признаки накрутки награды: рост `slow`, `mean b`, `tokens`, `ladder fail`. Файлы
  `runs/main/final/<вариант>/*.pairs.jsonl` содержат по 50 пар решений разных сидов для проверки вручную или LLM.
